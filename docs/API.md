# API

Status: Phase 1 draft for review. Tradelink has no public API. The browser talks to the app through **Server Actions** (forms and buttons) and a few **Route Handlers** (streaming, uploads, health, cron). Both call the `api` schema functions in `docs/DATA_MODEL.md` section 6.

## 1. Conventions

| Topic | Rule |
| --- | --- |
| Authentication | Supabase session cookie. Every action resolves the user on the server with `auth.getUser()`; unsigned calls return `TL401`. Admin actions also need an `aal2` session. |
| Authorisation | Done again in the database function (membership, role, ownership, state). The UI hiding a button is never the check. |
| Validation | Each action has a Zod schema in `src/features/<feature>/schemas.ts`. Strings are trimmed, lengths capped, numbers bounded, IDs are UUIDs. Unknown keys are rejected. |
| Result shape | `{ ok: true, data, message }` or `{ ok: false, error: { code, message, fields? } }`. `message` is the user-facing copy from DISCOVERY sections 6.8 and 6.9. |
| Idempotency | Actions marked (I) take `idempotencyKey: uuid`, generated by the client once per user intent (one tap of "Confirm and reserve stock"). The same key returns the first result without repeating the change. |
| Rate limits | ADR 0014. Over the limit returns `TL429`. |
| Errors | `TL400` invalid input (with `fields`), `TL401` not signed in, `TL403` not allowed (logged as denied), `TL404` not found or not visible, `TL409` conflict (`STOCK_SHORT`, `INVALID_TRANSITION`, `DUPLICATE`, `CUTOFF_PASSED`), `TL413` file too large, `TL415` file type not allowed, `TL429` rate limited, `TL500` unexpected (with request ID), `TL503` AI unavailable (fallback used). |
| Money | Decimal strings, `"52.00"`. Quantities are integers. Dates are `YYYY-MM-DD` in Asia/Singapore. |
| Caching | Pages that show stock or orders are dynamic. After a successful action the feature service calls `revalidatePath` for the affected routes. |

## 3. Route Handlers

| Method and path | Auth | Purpose | Notes |
| --- | --- | --- | --- |
| `POST /api/ask` | Buyer | Ask message; streams `text/event-stream` with `text`, `card` and `done` events | Body `{ message ≤ 2,000 chars, conversationId }`. Rate limited. Read-only tools (ADR 0009). |
| `POST /api/invoices` | Buyer | Multipart upload: `file`, `orderId`, `idempotencyKey` | JPEG, PNG, WebP, HEIC, PDF; ≤ 10 MB; ≤ 10 pages. Returns the invoice result or `needsManualEntry`. |
| `GET /api/invoices/{id}/file` | Buyer owner, supplier after query, admin | Redirects to a 60-second signed URL | Access logged. |
| `GET /api/health` | Public | Liveness `{ status: "ok" }` | No dependencies. |
| `GET /api/health/ready` | Admin session or cron secret for detail; public gets status only | Database, auth, storage reachable, with timings | |
| `GET /api/cron/health` | `CRON_SECRET` | Runs service checks | ADR 0013 |
| `GET /api/cron/email-outbox` | `CRON_SECRET` | Sends pending emails | |
| `GET /api/cron/daily` | `CRON_SECRET` | Expiry, cleanup, usage recalculation | |
| `GET /auth/callback` | Public | Supabase Auth code exchange (password reset links) | |

## 4. Read models by page

Pages are Server Components that read through the user's Supabase client (RLS applies).

| Page | Reads |
| --- | --- |
| Buyer Home | `v_week_spend`, `buyer_settings`, todos (price changes not acked, partials, issue replies not seen, invoices needing action, fee proposals, price rises), `v_restock_plan`, orders to check |
| Order | `order_drafts` + `draft_lines`, `v_catalogue`, `usual_items`, supplier cut-offs, delivery days and minimums |
| Orders and invoices | `v_order_cards` (own), open `issues`, `invoices`, `credits` |
| Ask | `ask_messages` (own) |
| Insights | `v_week_spend` (last 5 weeks), spend by supplier, `v_supplier_record`, `price_changes` for usual items, overcharges caught |
| Availability | `v_catalogue` with search and category filter |
| Settings | `buyer_settings`, `usual_items`, `team`, profile |
| Supplier Home | pending and to-deliver orders, open issues, unconfirmed and low products, last 2 `audit_log` rows for own org |
| Incoming orders | `v_order_cards` (to own org), open issues, negotiations |
| Inventory | own `products` + `inventory_levels` with search and low-stock filter |
| Stock history | own `stock_movements` (paginated) |
| Activity | `audit_log` where `related_org_ids` contains own org (paginated) |
| Supplier Settings | `supplier_profiles` (bank last 4 only), `team`, profile |
| Admin Home | `v_attention` (top 2), `audit_log` (2), low stock (2), `v_service_status`, operators online, unread notifications |
| Needs attention | `v_attention` + `attention_states` + admin users |
| Notifications | `notifications` (own org or platform) |
| All orders | `v_order_cards` (all), paginated |
| Suppliers, supplier profile | `v_admin_supplier_rows`, organisation, `supplier_profiles` (no HMAC), products, orders |
| Users, buyer details | `v_admin_buyer_rows`, all accounts with role and access summary |
| Operators | platform members with presence (last seen) and assigned item counts |
| System status | `v_service_status`, `ai_usage` totals |
| Audit log | `audit_log` (paginated, filter by organisation and outcome) |
